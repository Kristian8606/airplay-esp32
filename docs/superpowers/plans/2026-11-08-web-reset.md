# Web reset implementation plan

Goal: user-requested HomeKit reset and full factory reset in the existing web UI.
User delegates implementation choices ("измисли го"). Work only in the HomeKit
copy; preserve the pending README edit. No device reset/flash/commit/push.

Architecture: reuse the existing serialized HTTP task and its internal 8 KiB
stack, temporarily lowering its priority to 1 for maintenance. This costs no
new permanent task/stack. The existing web_audio_pause stops RTSP, waits for
session/settings workers and releases audio; never erase unless it succeeds.
Block reset until app_main finishes initialization. The HTTP task stays in
the handler through erase and reboot, so queued web setters cannot repopulate
old settings. Wi-Fi uses RAM storage and is not a persistent writer.

Scope:
- HomeKit: erase airplay/hk_pairs, ed25519_pub and ed25519_sec. Preserve all
  other NVS keys, including Wi-Fi/name/EQ/loudness/volume/latency. Restart so
  RAM pairings die and a new Ed25519 identity is generated on boot.
- Factory: physically erase the unused/legacy storage SPIFFS partition in
  bounded yielding chunks, then all default NVS. Preserve firmware/OTA boot
  data, hardware calibration and NVS encryption keys. Reboot to compiled
  defaults and Wi-Fi provisioning. No user configuration exists elsewhere.
- Auth: existing admin check, JSON-only strict mode+confirmation, bounded
  input, reject cross-site browser requests. UI confirms HomeKit; factory
  requires typing ERASE ALL. No destructive GET.
- Any erase failure reports failure and restarts; do not resume stale RAM
  state after a partial erase. Stop/release failure follows existing recovery.

Review focus: boot race; shutdown-triggered volume saves; queued web writes;
partial erase errors/power failure; Home app still holding its own pairing.
Power loss during flash erase can require repeating reset; do not claim an
atomic multi-key transaction or remotely deleting the Home app's record.

Files: main/device_reset.[ch] own HTTP validation/storage/reset sequence;
main/main.c marks ready; main/web_receiver.c registers; main/CMakeLists.txt
builds; data/www/index.html contains reset card and handlers; tests/reset
runs actual reset handler/storage logic with platform shims and browser JS.

PASS through Node REPL (no node executable on the local shell PATH); HomeKit
and FDK regression suites PASS. Both ESP32-S3 builds with IDF 6.0.2 PASS.
Independent read-only review: no actionable defects. Reviewer independently
ran backend suite and examined shutdown/startup/security/partition scope.
Known warnings: unused helper functions in existing FDK_audio.h; no reset-code
warnings. Ruling: reuse the HTTP task with temporary priority 1 instead of a
new worker; serialized setters and no extra persistent stack. Ready gate and
HAP-error recovery added to allow the requested recovery without startup races.
No reset, flash, commit or push performed. Hardware behavior is unverified.
